# AI Passport 双 Mac 语音控制面板

Apple Silicon Mac 原生菜单栏客户端与标准 FoloToy AI Passport 独立固件。设备选择运行主机和输入目标，按住上键说话，松开收尾；下键取消／返回。豆包负责识别，本项目不提供 ASR，不发送 Enter、不自动执行命令。

需求与已确认边界：[GitHub #1](https://github.com/CandySunPlus/ai_voice/issues/1)。术语见 [GLOSSARY.md](GLOSSARY.md)，跨端协议见 [docs/protocol.md](docs/protocol.md)。

## Mac 开发与启动

使用 Apple Silicon 原生 Swift 5.9+／Command Line Tools。部署目标为 macOS 11+；实际兼容性仍以对应系统的实机验收为准。客户端只依赖系统 AppKit、CoreAudio、Accessibility、CryptoKit、Security 和 Network；检查程序不依赖 XCTest 或宏插件。

```bash
bash scripts/check-macos.sh
bash scripts/package-macos.sh
open dist/AIPassport.app
```

打包产物使用本地 ad-hoc 签名，不是签名公证发行包。授权实际运行的 `AIPassport.app` 辅助功能；更新二进制后系统可能要求重新确认权限。没有截图识别，不要求屏幕录制权限；客户端只播放音频，不采集 Mac 麦克风。

菜单栏 `AI◉` 可打开面板、急停或退出。默认不自动监听、不自动启动登录项。正常退出、锁屏、睡眠和会话切换均清理录音；语音快捷键由独立子进程持有，父进程意外退出时通过管道关闭进行收尾。守护自身也被杀、权限被撤销或整机退出时，不能保证操作系统仍接受释放事件。

## 本机音频闭环（P0）

1. 安装 BlackHole 2ch：`brew install --cask blackhole-2ch`。管理员认证由用户完成。驱动文件安装后，可先结束会议／录音并重启 CoreAudio：`sudo killall -9 coreaudiod`，随后重新打开音频应用；本机已通过此方法免重启识别驱动。此命令会暂时中断所有声音与麦克风；无效时再按安装器要求重启整机，本项目不会自动重启。[官方重载说明](https://github.com/ExistentialAudio/BlackHole#build--install)
2. 在豆包中选择 BlackHole 2ch 为语音输入源；系统默认输出继续使用扬声器／耳机。客户端不会修改系统默认音频设备。
3. 先在空白“文本编辑”文稿中，用实体键盘验证豆包真实快捷键及模式，再勾选客户端的实体确认。当前开发机豆包 1.1.0 已实测其原有右 Option 免按模式：`keyCode=61`、`modifiers=0`、`mode=tap`；没有改动豆包的原有 Fn 长按设置，但 Fn 模拟未通过本次验证。另一台 Mac 仍需核对其真实设置，不能照抄 F9／Fn 示例。
4. 在面板选择 BlackHole 2ch，校准准备等待时间；设备显示录音后再开口。没有可靠输入法就绪回执，等待时间不是识别成功证明。

已在当前 Mac 完成本机合成语音闭环，以及修复版设备连续两轮无线人声出字；用户也确认焦点变化中断后重选恢复、录音中长按 OK 主动断连后重连恢复正常。完整稳定性批次、突发网络故障与两地主机使用尚未验收，具体边界见验收记录。

只读诊断：

```bash
dist/AIPassport.app/Contents/MacOS/AIPassport --diagnose
```

诊断不录音、不注入按键；设备与权限就绪也不代表豆包已经真实出字。

## 固件构建与实物核验

```bash
bash firmware/tools/bootstrap.sh
bash firmware/tools/build.sh
```

隔离安装 ESP-IDF 5.5.3、Python、CMake、Ninja 和 ESP32-C3 工具链，不使用 sudo，不修改系统或 shell 配置。输出 `firmware/build/full.bin`，写入偏移为 `0x0`；脚本没有刷写功能。设备端细节见 [firmware/README.md](firmware/README.md)。

**不要因为构建成功就刷写。** 每台实物都需核对 ESP32-C3／8 MB Flash／ES8311／240×320 三键硬件及官方恢复入口，说明原有应用和配置可能被覆盖，再单独取得刷写授权。本次目标已只读确认芯片／容量，并在用户另行授权后写入；板级及无线验收进展见 [验收记录](docs/acceptance.md)。原厂恢复依赖设备背面二维码中的专属链接和在线服务，不能承诺离线回滚；SN／KEY 不得上传仓库。

## 公司与家中配置

1. 每台 Mac 各自运行客户端，选择具体局域网 IPv4 接口及主机显示名，不使用 `0.0.0.0` 或公网地址。
2. 设备运行兼容面板固件后，接 USB、长按 OK 进入配置模式；在 Mac 选择对应串口，输入本地点的 2.4 GHz Wi-Fi，经 USB 保存网络和配对此 Mac。
3. 去另一地点重复配置。设备按 SSID／主机身份合并保存，各最多 4 个；Mac 密钥存登录钥匙串，设备凭证存本应用 NVS。
4. 启动 Mac 连接，在设备上明确选择单台运行主机，再选择输入目标。切换主机或重连都必须重新选目标，不续录旧语音。
5. 主机 IPv4 地址变化时重新经 USB 更新；建议在路由器设置 DHCP 地址保留。公司访客隔离网、需网页登录或企业认证的网络不能假定可直接使用，需要提供双方可互通的普通局域网。

## 安全与使用边界

- 控制 TCP、音频 UDP 均为 43821，只绑定选定本机局域网地址；独立密钥、会话随机数、HMAC、递增序号、ACK 和超时防止未授权控制与重复执行。
- **音频明文传输，仅每包鉴权，不是加密链路。只用于可信局域网，不做公网映射。** 未开启设备 Flash 加密时，不承诺抵抗物理提取 NVS 凭证。
- 所有音频缓冲有上限，录音最长 120 秒。默认不保存音频、转写、窗口正文或账号；豆包自己的云端处理和隐私策略另计。
- 仅自动操作当前桌面可唯一核验的普通窗口；重名、窗口重建、焦点失效、密码框、安全输入和锁屏均拒绝。无法确认时请在 Mac 手动点选，不能靠标题猜测。
- 录音中禁止切目标；焦点变化、断连或超时立即停音并清空缓冲。正常松键先排空尾部再结束豆包；出字时间须单独验收，用户应等文字完成后再操作。输入法已接收音频或已提交的文字不能由本项目撤回。
- 终端首版只输入文字，不自动回车；多行语音文本仍可能触发终端行为，首次必须在空白文本编辑文稿验收，不能在生产终端、密码框或高影响页面试验。
- Codex 现有桌面实例没有已验证实时接入来源，状态始终“未知”、数量不可用；不新建执行入口，不读取私有数据库或内部会话文件。

## 验收记录

自动协议检查覆盖跨语言 HMAC 向量、重复控制事件、篡改／旧会话重放、丢序、音频长度／鉴权、乱序恢复、有界尾部静音及公网地址拒绝。

在有局域网 IPv4 的 Mac 上另运行 `swift run ProtocolChecks --transport-rounds`，通过本机临时端口与测试密钥验证同一认证连接中的两轮 UDP 源端口变化；该检查不读取钥匙串、不打开音频、不注入按键，不能替代实体设备和豆包验收。

实机验证另见 [docs/acceptance.md](docs/acceptance.md)。编译、界面打开或协议检查通过均不能代替无线音频、豆包出字及设备稳定性验收。
