# AI Passport 独立语音面板固件

本目录是独立、完整的 ESP-IDF 5.5.3 工程，不是社区宿主移植模块。目标为官方标准 **ESP32-C3 / 8 MB Flash / 无 PSRAM / 240×320 / 三键**，复用固定版本官方 BSP，未保留硬件测试 demo 的菜单或界面。具体实物型号未知，构建不代表已确认兼容；**未经实物核验和再次授权，不刷写**。

线协议唯一契约：[../docs/protocol.md](../docs/protocol.md)。不使用未鉴权发现广播，也不保存音频或转写正文。

## 环境与构建

macOS（含 Apple Silicon）或 Linux 需要可用的 Git、Python 3（含 venv）、C 编译工具和网络。macOS 若未安装 Xcode Command Line Tools，先由用户人工安装；Linux 的编译器/系统开发包也由用户按系统策略安装。本脚本不使用 sudo，不安装 Homebrew，不修改 shell 启动文件或全局 Git/pip 配置。

在仓库根目录运行：

```sh
./firmware/tools/bootstrap.sh
./firmware/tools/build.sh
```

`bootstrap.sh` 在 `firmware/.deps/` 内隔离安装 uv 0.8.22、Python 3.12.11、CMake 3.31.6、Ninja 1.11.1.4、官方 ESP-IDF v5.5.3（实际提交 `2c211b236707889e8400c4dc5644dd5c4ee071e0`；上游 annotated tag 对象 `b31fcc7a314a44ad992b58f589f7d1d8a4fadff6`）及 ESP32-C3 工具链。ESP-IDF 源码及工具下载较大；失败后重新运行会复用已创建的目录。不切换网络镜像，不关闭 TLS 校验。安装与构建都不访问串口或设备。

可用 `PASSPORT_DEPS_DIR=/绝对路径` 改变隔离依赖目录。已有 5.5.3 安装可设置 `PASSPORT_IDF_DIR=/绝对路径`；该安装需已有可用的 Python、CMake、Ninja 环境。`PASSPORT_BUILD_DIR=/绝对路径` 改变输出目录。

输出：

- `firmware/build/full.bin`：从 **0x0** 起的合并镜像；脚本只生成，不写设备。
- 同目录的 `ai_passport_panel.elf`、`.map`、应用 `.bin`、bootloader 与分区表：保留以便与固件匹配调试。
- 构建配置在 `build/sdkconfig`，不覆盖开发者在工程根目录的 `sdkconfig`。

默认分区为 NVS + PHY + 单一 factory 应用，无 OTA/回滚槽。合并镜像的填充区域可能重置 NVS。官方恢复依赖机背专属恢复链接；其 SN/KEY 不得提交、截图到日志或上传。这里不承诺离线原厂恢复，不提供自动刷写脚本。

集成验证已运行 ESP-IDF 5.5.3 构建与合并镜像生成，产出 `build/full.bin`；未刷写或进行设备实测。首次构建需要下载锁定版本的 Managed Components。

## 操作

1. 上电首先显示保存的主机列表；WiFi 自动轮询已保存网络。上/下选择，OK 连接**显式选定**的主机。即使只有一台主机，也不会自动认领。
2. 鉴权完成进入输入目标列表，上/下选择，OK 确认。
3. 输入页：**按住 UP 说话**；收到已鉴权 `speak` 前不打开麦克风读取。松开停止，`stop.last` 是最后成功发送的 UDP 序号（未发送为 0）。DOWN 立即取消；空闲时 DOWN 返回目标列表。OK 空闲时回目标列表。
4. 录音/准备/尾音排空期间不切换主机或目标。长按 OK 可随时取消并退出会话，清除输入目标；主机列表再长按 OK 进入 USB 配置。
5. 主机列表长按 DOWN，切换到下一个已保存 WiFi。断网后自动轮询，每个网络最多尝试约 12 秒，循环失败明确提示重配。断连后必须重新显式选择主机，不恢复录音或目标。
6. 状态明确区分待命、目标确认、准备、录音、排空、等待焦点、错误；任务始终为未知，任务数量不可用。

所有按键仅入有界队列；UP 松开还直接设置原子停止标志，队列溢出则取消并断开，不允许漏掉松手后无限录音。异常、超时、取消、切主机和配置均清理旧采集；协作停止未完成时不允许开始新录音或写配置。

## 首次 USB 配置

USB 使用 C3 原生 USB Serial/JTAG（不占用与背光冲突的 UART0）。115200、UTF-8 JSONL。**必须先在设备主机列表长按 OK，屏幕出现“USB 物理配置模式”**。普通工作状态完全丢弃串口请求，`info` 也不响应，不能仅靠 Mac 命令进入配置。

Mac 配置页生成并保存主机身份及每设备独立的 32 字节随机密钥。设备接受协议中的 `info` / `configure` / `erase`，不接受其他操作：

- 多次配置按 SSID 合并网络，同 SSID 更新密码；按 ID 合并主机，同 ID 更新资料与密钥。每类最多 4 项，超限或任一字段无效会拒绝整个请求，不部分写入。
- 主机必须使用具体 IPv4 单播地址及端口 43821；不接受通配、回环、多播地址。仅支持 2.4 GHz 个人 WiFi / 开放网络，企业 802.1X 不在 SSID/密码配置模型内。
- 密钥是原始 32 字节的 64 位十六进制文本，不把十六进制字符当作 HMAC 密钥字节。
- 完整校验后以一个 NVS blob 提交，断电后不应出现一半新配置。设备 ID 独立保留，`erase` 仅清除本应用网络与配对，不擦除整个 NVS 分区。
- 成功只回应 `{"ok":true}`；不回显 WiFi 密码、密钥、请求正文。配置后长按 OK 退出，重新连接保存的 WiFi，再显式选择主机。
- 不要把含真实凭证的 JSON 存入 shell 历史或仓库。推荐只使用 Mac 配置界面，不使用带真实凭证的命令行参数。

## 协议与资源约束

`ap_link` 实现 TCP 43821、随机 nonce 双向 HMAC 身份证明、每次连接独立会话密钥、从 1 开始且不回绕的双向序号、重复消息仅 ACK、不重复执行、500 ms 保留原帧重传、2 秒未确认/3 秒无认证消息终止、1 秒 ping。消息类型或签名错误立即断开，输入目标随会话清除。

`ap_audio` 独占 BSP PCM 读操作，仅在 `speak` 后配置/唤醒 16 kHz、16-bit、mono；每 320 样本（20 ms）签名一个 APV1 UDP 包。全程只有一个 702 字节 PCM 包，无整段录音缓冲、文件或音频日志，120 秒或 6000 包后自动停止。UDP 明文；HMAC 仅提供来源/完整性校验，**不提供音频加密**。

JSON 解析使用固定 256 token / 8192 字节 / 八层嵌套上限，拒绝重复字段、坏 UTF-8、非法代理项、NUL、序号溢出和错误数字类型。控制接收、USB 接收、目标列表、重传队列和音频块都有固定上限；目标最多 12 项，ID 128、app/title 48、state.message 192 UTF-8 字节。主机/目标选择不写 Flash。

## 中文字形

内置衍生 **Passport Bitmap SC 16** 字库，源为 OFL Noto Sans CJK SC Regular 2.004，包含上游全部已映射 BMP 字形（常用简繁中文、扩展 A、拉丁文、标点等），不是把中文字符串放到英文字体里。字库约 2.06 MiB，位图直接从 Flash 索引，16×16 单字解码，不复制字库到 RAM。

非 BMP 字符（例如大部分 emoji）或源字库未映射的字以可见 `[U+1F600]` 等转义显示，不会显示空白或悄悄丢字。动态应用名/标题使用滚动文字显示；超长转义输出会用显式 `...` 标记。字体来源、固定提交、哈希和许可见 `assets/NOTICE.txt`、`assets/OFL.txt`。可在临时 Python venv 安装 Pillow 11.3.0 / fonttools 4.59.1 后，用 `tools/make_font.py 源OTF main/noto16.bin` 重建；普通固件构建不需要这些字体生成依赖。

## 人工验收（必须实机，先核验型号并取得刷写授权）

1. 核验 ESP32-C3、Flash 实际 8 MB、引脚/屏幕/三键符合官方 BSP，确认机背官方恢复路径可用。未满足时停在构建产物，不刷写。
2. 验证屏幕方向、颜色、圆角、中文“选择输入目标/准备就绪/任务未知”等字形；配置中文主机名，Mac 创建含简繁中文、ASCII `MW`、emoji 的标题，确认字形完整、英文不裁切、emoji 显示码点、长标题可滚动。
3. 正常模式发送 `info`、`configure`、`erase` 均无响应且配置不变化。仅物理长按 OK 后 `info` 返回协议声明。非法 JSON、重复字段、错类型、超长行不改变 NVS，不泄露请求内容。
4. 公司 WiFi + 公司 Mac 配置后，添加家中 WiFi + Mac mini，再重启；确认两个网络和两个主机均保留。同 SSID/主机 ID 更新不新增；第 5 个网络或主机整次拒绝，旧配置仍可用。物理模式 `erase` 后网络/主机列表清空。
5. 只连接显式选中主机；错误密钥、修改 welcome/signature、跳号、错类型均立即断开；相同序号重传只 ACK，不能重复 start/select。停止主机服务，验证超时和目标清除。
6. 未选目标、焦点不确定、Mac 锁屏或安全输入启用时，不得开始采集/输入。按住 UP 的准备阶段松手，不得在迟到的 speak 后开始录音。
7. 正常按住/松开 UP，确认非零 16 kHz 单声道 PCM、20 ms 包、APV1/HMAC/序号、stop.last 与最后包一致；120 秒自动停止；不自动 Enter、不发送、不执行转写。
8. 录音中 DOWN、长 OK、拔网/主机退出、目标失焦立即取消；旧 UDP 包和重连不能送入新目标。反复快速点按、排队按键和重连，不能续录、卡住快捷键或切换录音目标。
9. 两个 WiFi 都不可用时显示重配提示；长 DOWN 可切换已保存网络；断网恢复后仍要求重新选择主机与目标。
10. 连续多轮录音/UI更新/切换网络观察最小空闲堆、最大连续块和任务数；需要由集成方添加非敏感调试观察或使用调试器，不记录音频、窗口正文、密钥/密码。确认无重启、看门狗、泄漏或 UI 卡死。构建成功不等于此项已验收。

## 安全边界与当前限制

- HMAC 会话不等于加密局域网；只在可信 IPv4 局域网使用，不做公网端口映射。
- 未启用 Secure Boot / Flash Encryption；持有实物者可能读取 NVS 密钥与密码，不声称防物理提取。开启这些不可逆安全功能需要单独方案和授权，本工程不自动烧写 eFuse。
- USB 物理配置模式是人工授权门；该模式下连接的电脑可以配置或清除本应用凭证。离开设备前退出配置。
- 无 OTA、自动恢复或自动刷写；不保留原官方应用。电池读数/省电策略不作为本语音面板功能初始化，不改写未知实物的电池参数。
- 实物兼容、公司网络策略、麦克风增益/噪声、网络与 UI 同时运行的余量，以及 Mac 音频通路均未实测；集成方必须分别报告构建与实机结果。
