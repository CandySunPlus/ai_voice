# 0001：独立语音面板固件与显式运行主机

## 状态

已接受；用户在需求质询中确认。

## 背景

同一随身设备要在公司 Mac 与家中 Mac mini 使用。社区语音代码不是完整整机工程，原协议会发现单个对端且没有配对鉴权。直接沿用会把控制发给广播发现的主机，无法满足明确选择主机和输入目标的要求。

## 决策

以官方 AI Passport BSP 开发独立面板固件，不保留原固件的其他应用。首次通过 Mac + USB 保存多个网络与分别配对的主机；日常仅连接设备上显式选择的主机。切换主机、重连均清除输入目标和未完成录音。

配置协议与日常局域网协议见 [protocol.md](../protocol.md)。不用未鉴权广播选择运行主机；不接入云服务。

## 取舍

相较复用现成产品固件，需要自己维护配网、界面、字体和恢复说明；换来可审计的三键交互、主机身份和控制鉴权。设备保存的主机 IPv4 地址变化时需 USB 更新，建议为两台 Mac 配置 DHCP 地址保留。

不承诺保留原有应用或离线回滚。刷写前仍须核对实物、官方恢复入口和数据影响，并单独取得授权；本决定不是刷写授权。

## 替代方案

- 原样配置社区语音固件：不能提供完整目标列表及正式配对协议，下键 Enter 也不符合本版安全要求。
- 手机热点配网页面：用户选择由 Mac + USB 配置，避免额外的手机入口和热点管理。
- 自动选择发现的主机：用户选择显式单主机控制，避免语音投向非预期机器。
