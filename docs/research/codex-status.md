# Codex 桌面状态接入调研

## 公开接口的能力边界

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)描述客户端启动 `codex app-server` 后，通过 `initialize`、`thread/start`／`thread/resume` 和 `turn/start` 使用服务并接收事件。

- `thread/loaded/list` 列出该服务内存中加载的线程。
- `thread/status/changed` 通知该服务已加载线程的运行时状态。
- `thread/read` 不加载线程，返回的状态可以是 `notLoaded`；读取持久化历史不等于观察另一个进程的实时执行。
- 本次未找到官方承诺的第三方接口，可直接附着已运行的 Codex 桌面实例并订阅其中的实时线程／执行回合状态。不能据此断言所有版本都不存在私有接口，也不能把私有接口当稳定能力。

## 已确认的产品口径

用户选择保持现有 Codex 桌面使用方式，本项目不另建任务执行入口，不读取私有数据库或内部会话文件。没有可靠来源时，任务状态显示“未知”，数量显示不可用，不以 0 冒充没有任务。实时任务统计不作为本版交付承诺。

应用窗口存在、窗口标题、CPU 占用、历史记录均不得解释为任务正在运行或已经完成。

## 证据限制

本次为公开接口调研，未对用户的 Codex 桌面实例进行附着或实时事件实测。
